## 1. Classification Definitions

- **VERIFIED:** Functional and security behaviors demonstrated by source code, automated unit/integration test suites, or empirical compilation evidence.
- **PARTIALLY VERIFIED:** Core architecture and local implementation functional, but an essential real-world production behavior (e.g. complex font shaping, live network reconnection, multi-client concurrency) remains untested or incomplete.
- **BLOCKED BY EXTERNAL CREDENTIALS / ENVIRONMENT:** Cannot be tested without third-party vendor accounts, production merchant credentials, external services, or authenticated browser sessions.
- **NOT VERIFIED:** Code exists or claims were made, but no empirical test or execution evidence exists.
- **BROKEN:** Demonstrable defect, security hole, or runtime error identified.

## 3. Pre-Launch Mandatory Operations Checklist

Before pointing production traffic to `https://dairy.mtkcodex.site`:

1. **Environment Secrets Provisioning:**
   - Configure `CRON_SECRET` in production Vercel environment variables.
   - Configure `CLERK_SECRET_KEY` and `CLERK_WEBHOOK_SECRET`.
   - Configure `SUPABASE_SERVICE_ROLE_KEY` and production DB connection pooler string.
   - Configure `SENTRY_DSN` for server and client error telemetry.
2. **Pakistani Payment Rail Sandbox / Live Credentials:**
   - Onboard with JazzCash Merchant portal and obtain `JAZZCASH_MERCHANT_ID`, `JAZZCASH_PASSWORD`, and `JAZZCASH_INTEGRETY_SALT`.
   - Onboard with EasyPaisa merchant portal and obtain `EASYPAISA_STORE_ID` and `EASYPAISA_HASH_KEY`.
   - Verify webhooks point to `https://dairy.mtkcodex.site/api/payments/webhook/[gateway]`.
3. **Scheduled Cron Trigger:**
   - Set up scheduled HTTP requests (e.g. Vercel Cron or QStash) to call:
     - `GET https://dairy.mtkcodex.site/api/cron/predictions` daily with `Authorization: Bearer <CRON_SECRET>`
     - `GET https://dairy.mtkcodex.site/api/cron/reminders` daily with `Authorization: Bearer <CRON_SECRET>`
4. **Database Migration Verification:**
   - Ensure foreign key constraints on Phase 1 enhancement tables are fully applied in the live production Supabase instance.
5. **Dependency Maintenance:**
   - Address high/critical vulnerabilities identified in `npm audit` (`xlsx`, `websocket-driver`, `ws`) via targeted semver bumps.
